## High‑Level Architecture Overview

- **GameManager** (`GameManager.cs`): Singleton orchestrating the overall game state via the `GameStages` enum. It delegates user input to the relevant manager.

- **InputManager** (`InputManager.cs`): Uses Unity’s new Input System to translate player actions into calls on `GameManager`. Handles ray‑casts for object interaction.

- **BattlefieldManager** (`BattlefieldManager.cs`): Manages units on the battlefield, placement, selection, and special orders. Exposes helpers such as `TryAddUnit`.

- **Grid subsystem** (`GridController.cs`, `GridCell.cs`, `Tile.cs`): Implements a 2‑D grid. `GridController` keeps a dictionary of `GridCell` instances, each enforcing a single unit per cell.

- **Unit system** (`Unit.cs`, `UnitModel.cs`, `UnitInitialSetup.cs`): `Unit.cs` is a `MonoBehaviour` attached to unit prefabs. `UnitModel` loads data from a `ScriptableObject` (`UnitData`). `UnitInitialSetup` creates the initial unit list for both sides.

- **CameraController** (`CameraController.cs`): Smoothly follows a target via `Vector3.Lerp`. Exposes `MoveHorizontal(float amount)` for UI/input.

- **UI** (`UIManager.cs`, `DeployCardController.cs`): Handles UI panels and card deployment logic. `DeployCardController` communicates unit selection to `GameManager`.

## Key Patterns & Conventions

- **State machine**: `GameManager.GameStages` drives flow.
- **Event delegation**: `InputManager` forwards to `GameManager`, which then calls other managers.
- **ScriptableObject data**: Unit data lives under `ScriptableObjects/`.
- **Camera follow**: Smooth movement via `Vector3.Lerp`.
- **Grid placement**: `BattlefieldManager` relies on `GridCell.TryAddUnit` to enforce one unit per cell.

## Useful Notes

- Project uses Unity 2021.x and the Input System package.
- Unit tests reside in `Assets/Tests` and use the Unity Test Framework.
- When modifying core systems, update the corresponding `GameStages` or grid logic.
